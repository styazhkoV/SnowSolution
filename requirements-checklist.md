# Проверка качества бизнес-требований — часть 1

## Покрытие требований

- [x] Все требования имеют уникальные идентификаторы REQ-XXX.
- [x] Требования нумеруются последовательно.
- [x] Границы описаны только на основании наблюдаемого поведения проекта.

## Проверяемость

- [x] Для пользовательских сценариев приведены критерии приёмки в формате «Дано — Когда — Тогда».
- [x] Требования сформулированы независимо от деталей реализации, насколько это позволяет исходное поведение.
- [x] Успешность описана через измеримые и проверяемые критерии.

## Полнота

- [x] Указаны метод обследования, охват и ограничения доказательности.
- [x] Сценарии пользователя расставлены по приоритету.
- [x] Описаны функции запуска процесса, просмотра задач, завершения задачи и доступа через шлюз.
- [x] Ключевые сущности перечислены.
- [x] Неясные бизнес-правила и неподтверждённые возможности вынесены в допущения и вопросы.

## Следующие уточнения

- [ ] Утвердить правила доступа к задачам и право завершать задачу.
- [ ] Определить бизнес-данные, переменные процесса и правила валидации.
- [ ] Определить требования к хранению, истории, ошибкам, SLA и бизнес-метрикам.
